## เปิดบน Mac ใน VS Code

1. เปิดโฟลเดอร์ `FP` ใน VS Code
2. เลือก Terminal → New Terminal
3. รัน `python3 -m http.server 8000 --directory dist`
4. เปิด http://localhost:8000

ต้องเปิดผ่าน web server เพราะเบราว์เซอร์อาจปิดกั้น ES Modules หากเปิดไฟล์ `index.html` ตรง ๆ

## ขั้นวางแผน

1. **ข้อมูลการเงิน** — รายรับก่อนหัก/สุทธิ, รายการหักตามสลิป, PVD, ประกันสังคม และเงินได้ภาษี, รายจ่ายรายเดือน/ปี, สินทรัพย์, หนี้, Cash Flow รายเดือน และงบดุล
2. **ความคุ้มครอง** — กรมธรรม์ชีวิต/สุขภาพ/โรคร้ายแรง/บำนาญ และประกันวินาศภัย เช่น รถ บ้าน ขนส่ง เดินทาง อุบัติเหตุ ความรับผิดและธุรกิจ
3. **เป้าหมายและพอร์ต** — เป้าหมายหลายข้อ, ระยะเวลา, ความสำคัญ, เงินออม, คำแนะนำต่อข้อ, พอร์ต ต้นทุน มูลค่าปัจจุบัน กำไร/ขาดทุน ระยะเวลาถือ วันที่เงินพร้อมใช้
4. **เกษียณ** — อายุเกษียณ/สิ้นสุดแผน, เงินเฟ้อ, เงินที่ต้องใช้, เงินลงทุนที่ผูกไว้, RMF/SSF/Thai ESG/PVD/กบข./กอช., ประกันบำนาญ และยอดสิทธิประกันสังคมที่ผู้ใช้ประมาณเอง
5. **ภาษี** — อาชีพ/ประเภทเงินได้ 40(1)–(8), ค่าใช้จ่าย, ครอบครัว, ประกัน, เกษียณ, ดอกเบี้ยบ้าน, บริจาค, ภาษีที่จ่ายแล้ว และทดลองสิทธิออมเพิ่ม
6. **ภาพรวม** — ฐานะการเงิน, ช่องว่างความคุ้มครอง, ความพร้อมทุกเป้าหมาย, เกษียณ, ภาษี และรายการลงมือทำ

## การป้องกันนับเงินซ้ำ

- รายรับเลือกยอดก่อนหักหรือสุทธิได้ รายการหักประกอบด้วยประกันสังคม ภาษี รายการอื่น และเงินสะสมที่ผูกจากพอร์ต; เงินได้และภาษีหัก ณ ที่จ่ายทั้งปียังต้องยืนยันแยกตามหนังสือรับรอง
- PVD กรอกและแก้ในหน้าแรก ผูกกับรายรับรายเดือนหนึ่งรายการ หากกรอกรายรับสุทธิจะไม่หักซ้ำ เงินสมทบนายจ้างใช้ในการออมเกษียณ แต่ไม่ใช้ลดหย่อนภาษีของลูกจ้าง
- ประกันสังคมที่จ่ายเองนอกสลิปถูกบวกในรายจ่าย ส่วนที่ถูกหักจากสลิปไม่หักซ้ำจากยอดสุทธิ
- ยอดลดหย่อน PVD และประกันสังคมเลือกประมาณการยอดปัจจุบันเต็ม 12 เดือน หรือยอดจ่ายจริงตามหลักฐานได้ ไม่เปลี่ยน Cash Flow เมื่อแก้ยอดภาษี
- พอร์ตหนึ่งรายการเลือกปลายทางได้ครั้งละหนึ่งข้อ: เป้าหมายหนึ่งข้อ, เกษียณ หรือยังไม่จัดสรร
- กองทุนที่ยังขายไม่ได้ก่อนวันเป้าหมายจะไม่นำมานับเป็นเงินต้นที่พร้อมใช้
- เงินฝากหน้าแรกแยกจัดสรรเป็นเงินฉุกเฉินหรือปลายทางหนึ่งข้อ; บ้าน/รถรวมในสินทรัพย์สุทธิ แต่ไม่นับเป็นเงินต้นพร้อมลงทุน
- เบี้ยกรมธรรม์ต่อปีเฉลี่ยเข้ากระแสเงินสดตามรอบชำระ; ปีที่ชำระครบแล้วแต่คุ้มครองอยู่ยังคงมีผลคุ้มครอง
- ประกันบำนาญนำเข้ารายได้เกษียณตามอายุรับที่กำหนด

## ภาษี

ข้อมูลอ้างอิงที่ตรวจ 3 ตุลาคม 2569. หน้าแบบภาษีปี 2569 ของกรมสรรพากรที่ตรวจพบแสดงแบบครึ่งปี ภ.ง.ด.94; แบบยื่นสิ้นปีและมาตรการรายปีเพิ่มเติมต้องตรวจอีกครั้งก่อนยื่นจริง ระบบจึงใช้เพียงกฎพื้นฐานที่ยืนยันได้และมีช่องกรอกสิทธิเฉพาะหลังตรวจสอบ ไม่ส่งแบบภาษีและไม่รับรองยอดภาษี

ฐานข้อมูลทางการใน `dist/app.mjs` ลิงก์ไปกรมสรรพากรและ ก.ล.ต. ความหมาย 40(1)–(8), อัตราภาษี, แบบยื่นครึ่งปี, ภาษีประกันชีวิต/สุขภาพ/บำนาญ, RMF, Thai ESG, Thai ESGX, สิทธิจาก LTF และ SSF มีข้อจำกัดตามสถานะ บุคคลและปีภาษี

ค่าลดหย่อนภาษีขึ้นกับหนังสือรับรองและเงื่อนไขเฉพาะ แบบจำลองยังไม่รองรับทุกกรณี เช่น แยกคำนวณคู่สมรส ภาษีเงินได้ต่างประเทศ อนุสัญญาภาษีซ้อน ยอดยกเว้นผู้สูงอายุแบ่งหลายประเภท เครดิตเงินปันผลโดยละเอียด หรือธุรกิจ 40(8) ทุกชนิด ควรตรวจยอดกับผู้ทำบัญชี/กรมสรรพากรก่อนยื่น

## ขอบเขตการคำนวณ

- เงินลงทุนใช้ผลตอบแทนรายปีคงที่ แปลงรายเดือนและออมปลายเดือน ไม่ใช่ผลตอบแทนคาดการณ์รับประกัน, IRR, Monte Carlo หรือคำแนะนำหลักทรัพย์เฉพาะตัว
- กำไร/ขาดทุนพอร์ตคือมูลค่าปัจจุบันลบต้นทุนคงเหลือ ไม่รวมเงินปันผลที่ถอนออก และไม่คำนวณผลตอบแทนรายปี
- ช่องว่างทุนชีวิตใช้เงินครอบครัว + หนี้ + การศึกษา − สินทรัพย์ที่ผู้ใช้ระบุ ไม่ประมาณมูลค่าปัจจุบันของสวัสดิการ/ทุนประกันกลุ่มอัตโนมัติ
- เงินสำรองนับเงินสดที่จัดสรรเป็นฉุกเฉินเท่านั้น
- เงินบำนาญประกันสังคมเป็นค่าประมาณที่ผู้ใช้กรอก แอปไม่ตรวจประวัติการส่งสมทบหรือคำนวณสิทธิแทนสำนักงานประกันสังคม
- รองรับ Google Login + Firebase Cloud Sync เมื่อกำหนดค่าแล้ว; Local Storage และไฟล์สำรองยังทำงานเสมอ อ่าน CLOUD-SYNC.md ก่อนเปิด Cloud

## V2.3 — วิธีใช้ส่วนที่เพิ่ม

- จำนวนเงินเป็นช่องแป้นทศนิยม พิมพ์หรือวาง `1,250,000.50` ได้; ออกจากช่องแสดง comma และอย่างน้อย 2 ตำแหน่งทศนิยม เข้าช่องนำ comma ออก ไม่เปลี่ยนค่าเป็นข้อความในโมเดล อายุ ปี จำนวนคน และเปอร์เซ็นต์ไม่จัด comma
- ช่องเงินที่ยังไม่ยืนยันแสดงว่าง; 0 หมายถึงยืนยันว่าไม่มีเงินส่วนนั้น ปุ่ม “ยังไม่ทราบ” เก็บสถานะแยกจากตัวเลข ไม่ล้างค่าที่เคยกรอก และไม่แสดงผลรวมจนแก้สถานะดังกล่าว
- ค่าตั้งต้นของอายุ ระยะเวลา และผลตอบแทนเป็นสมมติฐานที่ต้องทบทวน ช่องเสริมที่ว่างยังไม่นำมารวม (ค่าตั้งต้นเงินส่วนเสริมเป็น 0) ช่องจำเป็นตรวจการกรอกแยกจากค่าเริ่มต้น
- ถาม “ยังไม่ตอบ / มี / ไม่มี” ก่อนแสดง PVD ประกัน พอร์ต รวมถึงรายรับ รายจ่าย สินทรัพย์ หนี้ และเป้าหมาย ถ้ามีรายการเดิมจะคงแสดงไว้ การเลือกไม่มีไม่ลบรายการ ต้องลบผ่านปุ่มของรายการและสามารถเลิกทำได้
- รายการใช้ `<details>` พับได้ หัวแสดงชื่อและยอดสำคัญ
- เมนูแสดงยังไม่เริ่ม / กำลังกรอก / กรอกครบ / เลือกข้าม การกรอกครบต้องมีข้อมูลจำเป็นและกดตรวจทานสมมติฐาน; เปลี่ยนข้อมูลจะยกเลิกการยืนยันเดิม การข้ามไม่ลบข้อมูลและไม่ยกเลิกยอดที่เชื่อมกับหน้าอื่น
- การจัดสรรแสดงยอดเงินสดและพอร์ตที่จัดสรรแล้ว/ยังไม่จัดสรร และยังใช้ปลายทางเดียวต่อหนึ่งรายการตามสูตรเดิม บ้าน/รถไม่เป็นเงินพร้อมจัดสรร
- หน้าสรุปแยกสถานะปัจจุบัน ข้อมูลขาด และสิ่งที่ทำต่อ แสดงรายละเอียดเฉพาะส่วนที่พร้อม และคงคำสั่งพิมพ์ รายละเอียดแบบพับเปิดก่อนพิมพ์โดยอัตโนมัติ
- ยอด “ออมเกษียณเพิ่มจากที่วางไว้” ในสรุป = max(0, extraNeeded เดิม − เงินออมเพิ่มนอกพอร์ตที่กรอกแล้ว) เป็นการนำผลเดิมมาแสดงให้ตรงความหมาย ไม่แก้สูตรโมเดล กรณีเกษียณแล้วแสดงเงินก้อนที่ยังขาดแทนยอดรายเดือน

## การบันทึกและกู้คืน

Local Storage key: `fp.plan.v2.3` V2.4 บันทึกทันทีเมื่อ state เปลี่ยน และหน่วง Cloud Sync 1.5 วินาที และพยายามบันทึกเมื่อออกจากหน้า มีสถานะกำลังบันทึก / บันทึกแล้ว / บันทึกไม่สำเร็จ

การเก็บข้อมูลผูกกับ origin (โปรโตคอล โฮสต์ และพอร์ต) เช่น localhost:8000 กับเว็บไซต์จริงเป็นคนละที่ และคนละเบราว์เซอร์ก็ไม่แชร์ข้อมูล การล้างประวัติเบราว์เซอร์อาจลบข้อมูลแผนได้ จึงควรดาวน์โหลด JSON สำรอง

หากอ่านข้อมูลเก่าไม่ได้หรือโครงสร้างเสีย ระบบแจ้งและล็อกการเขียนทับตลอดการใช้งานครั้งนั้น ใช้ปุ่มดาวน์โหลดข้อมูลที่บันทึกดิบเพื่อเก็บต้นฉบับ แล้วใช้ล้างข้อมูลพร้อมยืนยันเพื่อเริ่มใหม่ หากลบไม่ได้จะไม่อ้างว่าลบสำเร็จ การนำเข้า JSON ขณะล็อกยังใช้ดูแผนได้แต่ไม่ปลดล็อกการเขียนทับอัตโนมัติ

V2.4 ใช้ JSON schema version 6 เดิม และ appVersion 2.4.0; รับ schema 1–5 ผ่านตัวแปลงเดิมและ schema 6 ที่มีข้อมูลสถานะ `ux` เวอร์ชัน V2.2 ไม่รองรับไฟล์ schema 6 เพื่อป้องกันการนำค่าที่ยังไม่ทราบไปใช้โดยไม่อ่านสถานะ ไฟล์เก่าที่ไม่มีสถานะยังไม่ทราบจะถือค่าที่มีเป็นข้อมูลนำเข้า แต่ต้องทบทวนก่อนกรอกครบ รายการว่างจากไฟล์เก่ายังต้องตอบว่ามีหรือไม่มี

## ประวัติผลทดสอบ V2.3 (ก่อนเพิ่ม Cloud)

`node tests.mjs` ผ่านทั้งหมด: 4 ไฟล์ทดสอบเดิม (ปรับ DOM harness ให้โหลดโมดูลใหม่และกำหนด fixture ตามพฤติกรรมเดิม) และ `v23-experience.test.mjs` เพิ่มกรณี comma/ทศนิยม, ว่าง/ศูนย์, คืนค่า, storage failure, ข้อมูลเสียไม่ถูกเขียนทับ, ยืนยัน/ยกเลิกล้างข้อมูล, นำเข้าแผนเก่า, สถานะความครบถ้วน และข้ามรายงานไม่สร้างยอดศูนย์

ในการส่งมอบ ZIP V2.3 เดิมยังไม่ได้ตรวจภาพในเบราว์เซอร์จริง: เครื่องไม่มี Chromium และการดาวน์โหลดผ่าน Playwright ล้มเหลว (ไฟล์ดาวน์โหลดไม่ใช่ ZIP ที่สมบูรณ์) จึงยังไม่ยืนยันการแสดงผล desktop/mobile หรือ PDF จริง แม้เพิ่ม CSS คอลัมน์เดียว ปุ่มขั้นต่ำ 44 px ตารางเลื่อน และตรวจ event handlers ด้วย DOM จำลองแล้ว

มีสคริปต์ browser smoke test เตรียมไว้ แต่ยังไม่ได้รันผ่าน:

```sh
# ต้องติดตั้ง Node.js, Playwright และ Chromium ในเครื่องทดสอบ
npm install --no-save playwright
npx playwright install chromium
# terminal แรก
python3 -m http.server 8000 --directory dist
# terminal อีกหน้าจากโฟลเดอร์ FP
node tests/browser-check.cjs
```

สคริปต์เตรียมทดสอบทั้ง 6 หน้าที่ความกว้าง 1440/390 px และเก็บภาพใน `test-artifacts/` ไม่ใช่ dependency สำหรับเปิดใช้งานเว็บ

### เส้นทางกรอกแบบใหม่

เริ่มจาก 5 ขั้น: รู้จักคุณ → เงินเข้า → เงินออก → เงินที่มี → สรุป เลือกวางแผนเกษียณ ครอบครัว เป้าหมาย และภาษีเพิ่มเติมจากหน้าสรุปได้ รายการที่พักไว้แสดงปุ่มกลับไปเติมตรงขั้นเดิม ส่วนการแก้ไขทุกหมวดอยู่ในตั้งค่า / บัญชี

มีทางลัด **ภาษี / เกษียณ / ครอบครัว / เป้าหมาย** ในทุกขั้น พร้อมกลับไปจุดที่กรอกค้างไว้ รายการด่วนช่วยเพิ่มชื่อและรูปแบบโดยไม่สมมติยอดเงิน และหน้าสรุปมีลิงก์ไปยังช่องที่ยังต้องเติม
